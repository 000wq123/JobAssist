Warum Split-View, warum jetzt

Eine Auflösung, zwei Aufmerksamkeiten.

  • 1 Mobile bleibt unverändert. Unter 1024 px kollabiert das Layout zur bekannten Stack-Navigation — Liste → Detail → Zurück. Der Split aktiviert sich erst, wenn die Breite es trägt.
  • 2 Die Liste verliert nie den Kontext. Man scannt 9 Jobs links, eine Auswahl links bleibt sichtbar (Akzent-Border, sanfter Tint) — rechts liest man, ohne navigieren zu müssen.
  • 3 Die Lesebreite ist begrenzt. Detail-Inhalt steckt in einer 760 px Lese-Säule — auch auf 1920 px wird Text nicht zur Tapete. Der Rest ist atmender Raum.
  • 4 Drei unabhängige Scroll-Container. Sidebar (kurz, statisch), Liste (eigener Scroll), Detail (eigener Scroll). Kein Layout-Sprung, wenn man wechselt.

Implementierungs-Notiz

React-seitig: JobsLayout wrappt <Outlet />. Auf lg+ rendert es zwei Spalten, die JobsPage bleibt links montiert; JobDetailPage rendert in Outlet rechts. Routing bleibt /stellen · /stellen/:id — kein Modal-Hack, kein State-Lifting.

Wenn das hier sitzt, kommt v8: Finden-Feed im Desktop-Format (Stack links, Detail-Vorschau rechts) — gleicher Pattern, anderer Inhalt.
